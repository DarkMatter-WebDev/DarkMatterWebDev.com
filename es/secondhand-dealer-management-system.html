El problema

El cumplimiento de Florida no deberia vivir en hojas de calculo.

El Estatuto de Florida 538 exige registros estrictos: verificacion de ID del vendedor, huellas, firmas, registros de articulos, retenciones minimas de 15 dias y reportes diarios para la policia. SDMS integra esos requisitos en el flujo de trabajo para que el personal opere mas rapido y con menos riesgo.

Que construi

Cumplimiento aplicado en la capa de datos, no solo en la interfaz.

  • lockLa retencion de 15 dias se aplica en el servidor y rechaza ventas antes de que el articulo quede libre.
  • historyRegistro de auditoria inmutable para cada operacion de escritura.
  • no_deleteSin borrados definitivos en tablas relevantes para cumplimiento.
  • badgeAuth JWT personalizada con bcrypt y roles de dueno, gerente, empleado y auditor.
  • printImpresion de recibos y etiquetas de inventario configurables para tamanos tipo Dymo/Zebra.

Detalles tecnicos

  • apiBackend Python 3 / FastAPI.
  • webFrontend React 18 / TypeScript / Vite / Tailwind.
  • databasePostgreSQL en Neon, desplegado con Render + Netlify.
  • desktop_windowsInstalador Windows desde el mismo codigo con PyInstaller, Nginx, PostgreSQL incluido e Inno Setup.
  • monitoringPrecios de metales por Yahoo Finance futures y calculos de fundicion con Decimal.
