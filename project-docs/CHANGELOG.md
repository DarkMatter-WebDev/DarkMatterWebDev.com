- **Fixed the estimate pill bleeding through the back of a flipped card, mirrored — on real phones/tablets only.** Reported from a device; desktop never showed it. Cause: `.poke-card` is `transform-style: preserve-3d` and `.poke-face` is `transform-style: flat`, so on desktop the pill is flattened into the face's own rasterisation and hides with it. Mobile GPUs promote an absolutely-positioned, z-indexed element to its own compositing layer — which escapes that flattening, joins the card's 3D context, and (at the default `backface-visibility: visible`) paints its backface through the flipped card. Audited every descendant of the front face: `.tcg-stat-pill` was the **only** one that promotes, which is exactly why only the price label bled and nothing else did. Fixed with `backface-visibility: hidden` (+ `-webkit-`) on the pill in `assets/collectible-card.css` → `v=20260716-pill-backface` (2 pages). **This is not a dev-server artifact — it would have shipped**; the server sends identical CSS, only the browser differs.
- The widget had already solved this for itself and it doubles as the proof: `.poke-glare` is the same shape of element (absolute, z-indexed, in the 3D context) and carries an explicit `backface-visibility: hidden` with the comment "only reveal the glare on the side currently facing the viewer". The glare does **not** bleed through on the reporter's device, which is direct evidence that the property is honoured there — so the pill, now matching it, should behave the same. **Any future overlay added inside a card face needs this property**; noted in the file's comment.

- **The table scroll hint now repeats instead of firing once** (`assets/table-scroll-hint.js` → `v=20260716-table-hint-repeat` on its 3 pages). A single nudge on scroll-into-view is easy to miss if the reader happens to be looking elsewhere on the page, so it now nudges every ~4s of stillness (~5s cycle including the ~1.05s animation) for as long as the table is in view and the reader hasn't engaged. Turning a one-shot into a loop moved all the weight onto the stop conditions, so those got the attention: engagement listeners are now armed for the whole cycle rather than only during an animation (previously interaction during the quiet gap wouldn't have registered); leaving the viewport **pauses and rewinds** rather than nagging an offscreen table — the rewind matters because a nudge aborted mid-travel would otherwise leave `scrollLeft > 0` and be misread on return as the reader having scrolled it; and because a loop can't ignore what a one-shot could, it now also listens for `prefers-reduced-motion` switching on mid-session (stops for good) and for crossing the 1279.98px desktop line (parks, and un-parks on the way back — without this the cycle would die at desktop and never resume). Unchanged: user-driven events only (`pointerdown`/`touchstart`/`wheel`/`keydown`) since our own animation writes `scrollLeft` and would race a `scroll` listener; a table the reader already scrolled is still never touched; still generic (walks up from every `<table>`, no opt-in); still silent with no real overflow.
- **Capped at `MAX_NUDGES = 6`** (~30s of intermittent motion), which also settles the WCAG 2.2.2 (Pause/Stop/Hide) exposure that unbounded motion beside readable text would have carried: six is well past "they missed the first one", and someone who has ignored that many has seen it and chosen not to scroll. Counted per page load, not per time in view. The cap is checked at the top of `run()` rather than only where the next nudge is queued — a table that goes offscreen mid-cycle re-enters through `evaluate()`, which would otherwise walk straight past a spent budget (verified: burn 3 → hide → show → still stops at exactly 6). On reaching it the entry retires through the same `stop()` path as engagement, releasing listeners and unobserving rather than idling observed-but-silent. `engaged` renamed to `done` since retiring now means "reader took over **or** we've said our piece".
