- **The site's mobile/desktop breakpoint is 880px — one line for everything.** Below 880: hamburger, bottom tab bar, mobile page layout, mobile footer. At 880+: full header with Contact CTA, wide layout, wide footer. Two halves keep this true and must stay in step:
  1. **Tailwind `md:`** is retargeted to 880 via `"screens": {"md": "880px"}` in each page's inline `tailwind.config` (and in `assets/tailwind-nav-config.js`). **A new page must include it**, or its layout will flip at Tailwind's stock 768 while the nav flips at 880 — which is exactly the bug that produced a mobile bar over a squeezed desktop grid.
  2. **Hand-written media queries** use `max-width: 879.98px` / `min-width: 880px`. Never write 767/768 in site CSS.
  Exceptions, on purpose: `account-admin/-settings/-users` + `app-checkout` (no `md:` utilities, no nav loader), and `client-portal.css` (700/860px are its own component reflow points).
- Homepage wide hero (`#hero`) is `min-height: min(100vh, 1000px)`; mobile hero (`#hero-mobile`) is `min-height: min(74vh, 700px)`. The 74vh ratio is tuned for phones; the 700px cap stops the flex stage from opening a ~450px void above the Contact CTA on tall tablet-sized windows that still get the mobile layout (<768px). Reach for the cap, not a width breakpoint — a breakpoint jumps the hero the moment it is crossed. The `min-h-[100vh]` class on the section is overridden by this rule.
- Favicon (2026-07-16) is the Material Symbols `blur_on` glyph in electric cyan on the void-black rounded square — the same mark the shared footer uses. Source of truth is `assets/favicon.svg`; the PNGs (`favicon-32/192/512.png`, `apple-touch-icon.png`) are rasterised from it, so **regenerate them from the SVG rather than editing them directly**. apple-touch-icon is intentionally an opaque square (iOS masks and rounds it itself); the others keep transparent corners. - **Footer single source of truth (2026-07-16):** every public page injects its footer from `assets/standard-site-footer.js` via one tag — `<script src="assets/standard-site-footer.js?v=20260716-shared-footer">` (add `data-variant="desktop"` / `"mobile"` inside each wrapper on the two-layout pages; `../assets/...` under `services/`). No page carries inline footer markup, and the old `.app-footer` / `.service-mobile-footer` / `.portfolio-hub-footer` variants are gone. **Do not hand-copy footer HTML into a page — add the loader tag.** Two variants match the homepage: `.dm-footer` (≥768px, full link list + tagline) and `.dm-footer-mobile` (<768px, centered, short labels, brand mark). Styled as plain CSS in `nav.css`, deliberately: the Tailwind CDN only builds utilities present in a page's *static* HTML, so injected markup cannot rely on them (`text-on-primary-container/60` rendered white when tested that way). Same reason `nav.css` pins the hamburger line colours.
- Horizontally-scrollable tables self-announce: `assets/table-scroll-hint.js` nudges any overflowing table ~52px right and back **and repeats every ~4s of stillness, up to `MAX_NUDGES = 6`, while the table is in view and the reader hasn't engaged** (2026-07-16 — one nudge was easy to miss if it fired while they were looking elsewhere; the cap keeps ~30s of intermittent motion clear of WCAG 2.2.2). Tablet/mobile only, skipped under `prefers-reduced-motion`. It finds the scroll container by walking up from every `<table>`, so new tables are covered automatically — do not add a per-table class or opt-in. Loaded on `services/website-design-hosting.html`, `account-admin.html`, `account-users.html`. **Because it loops rather than firing once, the stop conditions are the load-bearing part** — any interaction (`pointerdown`/`touchstart`/`wheel`/`keydown`) ends it permanently, a table the reader already scrolled is never touched, leaving the viewport pauses and rewinds it (so a half-finished nudge isn't later misread as the reader having scrolled), and switching to reduced-motion or a desktop width mid-session stops/parks it. The cap is checked at the top of `run()`, not only where the next nudge is queued, because a table that goes offscreen mid-cycle re-enters via `evaluate()` and would otherwise walk past a spent budget.
- The fixed mobile bottom tab bar (5rem) covers the end of the page, so `nav.css` gives every footer `margin-bottom: calc(5rem + env(safe-area-inset-bottom, 0px))` under 768px — one rule owns this. Use a **margin on the footer, not padding on the body/wrapper**: the footer must stay flush against the bar so the bar's blur sits over the footer's own background; padding lifts it and exposes the fixed starfield behind. Do not add per-page bottom padding for bar clearance (that double-counts — `index.html`'s `mb-20` and the removed service-wrapper `pb-24` were the old per-page way).
- The fixed nav measures ~101px at ≥768px and 64px for the mobile header. Anything relying on an anchor offset must clear its own nav: the pricing page uses `section[id] { scroll-margin-top: 145px }` with a `110px` override under 768px. A single shared value does not work for both.
